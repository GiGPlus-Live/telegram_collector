# کالکتور تلگرام به Matrix

[English README](README.md) · **فارسی**

**Telegram Collector** یک برنامهٔ خودمیزبان با پنل انگلیسی و فارسی است. پیام‌های جدید کانال‌های تلگرام را پایش می‌کند و متن و رسانهٔ آن‌ها را طبق قواعدی که تعیین می‌کنید، به یک یا چند اتاق Matrix می‌فرستد. یک منبع تلگرام می‌تواند هم‌زمان به مقصدهای مختلف روی یک یا چند سرور Matrix ارسال کند.

پنل به‌طور پیش‌فرض به انگلیسی باز می‌شود. از صفحهٔ ورود، نوار بالای پنل یا داخل هر پنجره می‌توانید به فارسی بروید. مرورگر انتخابتان را برای بازدید بعدی نگه می‌دارد.

[ایمیج Docker Hub](https://hub.docker.com/r/gigplus/telegram_collector) · [راهنمای رمزنگاری و تأیید دستگاه](docs/ENCRYPTION_SETUP.md) · [متن صفحهٔ Docker Hub](docs/DOCKER_HUB.md)

## ۱. نصب و راه‌اندازی

پیش‌نیاز شما Docker و Docker Compose نسخهٔ ۲ است. پس از دریافت سورس، در پوشه‌ای که فایل [compose.yaml](compose.yaml) قرار دارد اجرا کنید.

```sh
docker compose up -d --wait
```

Compose ایمیج `gigplus/telegram_collector:latest` و MongoDB را اجرا می‌کند. در نصب تازه، حساب‌ها و کانال‌ها خالی هستند و برنامه کلید امضای نشست پنل را خودکار ایجاد می‌کند. برای راه‌اندازی به فایل `.env` نیازی نیست.

- **روی سیستم خودتان** پنل را در [localhost:3080](http://localhost:3080) باز کنید.
- **روی سرور** از آدرسی مثل `http://SERVER-IP:3080` استفاده کنید. پورت میزبان با گزینهٔ اختیاری `PORT` قابل تغییر است.
- نام کاربری و رمز نخستین ورود هر دو `admin` هستند. پس از ورود از **امنیت و 2FA** رمز اولیه را عوض کنید.
- برای فعال‌سازی ورود دومرحله‌ای، QR را با برنامهٔ Authenticator اسکن کنید یا کلید دستی را وارد کنید. سپس کد شش‌رقمی را در پنل تأیید کنید. بعد از فعال‌سازی، این کد در ورودهای بعدی به پنل لازم است.

اگر فقط ایمیج را می‌خواهید، نمونهٔ کامل و قابل کپی Compose در [README مخصوص Docker Hub](docs/DOCKER_HUB.md) آمده است.

## ۲. اتصال تلگرام و پروکسی

1. اگر سرور به پروکسی تلگرام نیاز دارد، از **تنظیمات پروکسی** پروتکل، هاست و پورت را وارد کنید. برای SOCKS اطلاعات ورود را در صورت نیاز وارد کنید. برای MTProto مقدار Secret را وارد کنید. سپس پروکسی را فعال و ذخیره کنید.
2. در **اکانت‌های تلگرام** روی **ورود اکانت تلگرام جدید** بزنید و کشور، شمارهٔ همراه، `API ID` و `API Hash` را وارد کنید. دو مقدار API را از یک برنامه در حساب تلگرام خودتان بگیرید. [راهنمای رسمی دریافت مشخصات API](https://core.telegram.org/api/obtaining_api_id)
3. کد ورود تلگرام و در صورت درخواست، رمز دومرحله‌ای خود حساب تلگرام را وارد کنید. حساب را در حالت فعال نگه دارید تا برای پایش استفاده شود.
4. بعد از ثبت حداقل یک حساب فعال، دکمهٔ **تست اتصال پروکسی** برای پروکسیِ ذخیره‌شده و فعال در دسترس قرار می‌گیرد. تست واقعاً به سرور تلگرام وصل می‌شود و زمان پاسخ را نشان می‌دهد.

پروکسیِ پنل برای احراز هویت، پایش و دانلود تلگرام استفاده می‌شود. اتصال به Matrix از مسیر مستقیم برنامه برقرار می‌شود. پروکسیِ فعال مسیر اجباری اتصال تلگرام است و خرابی تنظیمات می‌تواند اتصال را متوقف کند. پروتکل‌های قابل استفاده برای اتصال تلگرام SOCKS4، SOCKS5 و MTProto هستند.

برای کانال خصوصی، حسابی که پایش را انجام می‌دهد باید در تلگرام به کانال دسترسی داشته باشد. برای کانال عمومی می‌توانید یوزرنیم یا لینکی مثل `https://t.me/example_channel` را وارد کنید.

## ۳. ثبت سرور و مقصد Matrix

1. در **سرورهای ماتریکس** روی **افزودن سرور ماتریکس** بزنید. یک نام، آدرس سرور و شناسهٔ حساب بات مانند `@collector:example.org` وارد کنید. دامنهٔ خالی مانند `matrix.example.org` خودکار با `https://` تکمیل می‌شود. اگر `https://` یا `http://` را وارد کرده باشید، همان پروتکل حفظ می‌شود.
2. توکن دستگاه بات را وارد کنید یا با رمز همان حساب، **دریافت خودکار توکن** را بزنید. می‌توانید اتاق پیش‌فرض را هم در رکورد سرور ذخیره کنید. **تست اتصال** دسترسی حساب را بررسی می‌کند.
3. مطمئن شوید بات عضو اتاق مقصد است و مجوز ارسال پیام دارد. از **تعریف کانال ماتریکس جدید** یک مقصد بسازید و سرور آن را انتخاب کنید.
4. آدرس اتاق را با یکی از قالب‌های زیر بدهید. برای هر مقصد هم وضعیت فعال، عنوان، نوع رسانه و سقف آپلود را تنظیم کنید.

| نوع آدرس | نمونه |
| --- | --- |
| نام عمومی اتاق (Alias) | `#news:example.org` |
| شناسهٔ اتاق (Room ID) | `!room123:example.org` |

ثبت چند مقصد برای یک سرور و استفاده از چند سرور Matrix پشتیبانی می‌شود. هنگام تعریف کانال تلگرام، می‌توانید مقصد جدید را هم از همان فرم بسازید.

### ورود مجدد بعد از تغییر رمز

اگر تست اتصال **نیاز به ورود مجدد** نشان داد، کنار همان سرور روی **ورود مجدد** بزنید و رمز جدید **همان حساب بات** را وارد کنید. توکن روی همان رکورد به‌روز می‌شود و مقصدها، نگاشت کانال‌ها و محدودیت‌های رسانه حفظ می‌شوند. اگر Matrix نشست قبلی را کاملاً لغو کرده باشد، نشست تازه شناسهٔ دستگاه جدیدی دارد که می‌توانید آن را از **تأیید دستگاه** تأیید کنید. [مدیریت ورود مجدد و دستگاه‌ها](docs/ENCRYPTION_SETUP.md#ورود-مجدد-پس-از-تغییر-رمز-بات)

## ۴. تنظیم پایش و قوانین رسانه

در **مدیریت کانال‌های تلگرام** روی **ثبت کانال** بزنید. یوزرنیم یا لینک کانال، عنوان نمایشی، بازهٔ بررسی و مقصدها را تعیین کنید. بازهٔ پیش‌فرض **۶۰ ثانیه** و حداقل آن **۱۰ ثانیه** است. کانال فعال وارد چرخهٔ پایش می‌شود. اولین بررسی یک نقطهٔ شروع می‌سازد و پیام‌های بعد از آن پردازش می‌شوند.

| سطح تنظیم | چه چیزی کنترل می‌شود؟ |
| --- | --- |
| **دانلود از تلگرام** | حالت فقط‌متن، سقف کلی حجم هر فایل و سقف جداگانه برای عکس، ویدئو، صدا، سند و استیکر. هر دسته کلید فعال یا غیرفعال مستقل دارد. |
| **آپلود به Matrix** | همان دسته‌ها و سقف‌های حجم به‌صورت جدا برای هر اتاق مقصد. یک اتاق می‌تواند فقط متن و اتاق دیگر متن و رسانه دریافت کند. |

عدد **۰** یعنی برای آن فیلد سقف حجم تعیین نشده است. اگر سقف کلی و سقف دسته هر دو تنظیم باشند، محدودیت کوچک‌تر اعمال می‌شود. سقف‌ها در پنل بر حسب MB نمایش داده می‌شوند و برنامه هر واحد را معادل `1024 × 1024` بایت حساب می‌کند. سقف آپلود خود سرور Matrix هم همچنان اعمال می‌شود.

برای نمونه، یک کانال تلگرام با سقف دانلود ۱۰ MB را به سه مقصد وصل کنید. در مقصد اول سقف آپلود را ۵ MB بگذارید، در مقصد دوم ۱۰ MB و مقصد سوم را «فقط متن» کنید. اگر قواعد دستهٔ ویدئو اجازه بدهند، یک ویدئوی ۷ MB فقط به مقصد دوم می‌رود. متن یا کپشن همراه آن می‌تواند به هر سه مقصد برسد.

در تنظیمات پیشرفتهٔ کانال تلگرام، آدرس مستقیم اتاق‌ها را هم می‌توانید با کاما از هم جدا کنید. ارسال مستقیم از سرور مرتبط با آن کانال یا تنظیم پیش‌فرض سرویس Matrix استفاده می‌کند. با مقصدهای ثبت‌شده در پنل، انتخاب سرور و سقف آپلود هر اتاق روشن‌تر است.

بعد از اولین بررسی، یک پیام تازه در کانال آزمایشی تلگرام بفرستید. پس از چرخهٔ بعدی پایش، متن و رسانهٔ مجاز را در مقصدها بررسی کنید.

### نحوهٔ ادامهٔ پردازش

- Collector تاریخچهٔ تازه را صفحه‌بندی می‌کند، پیام‌ها را به ترتیب پردازش می‌کند و فایل‌های آلبوم را با هم در نظر می‌گیرد.
- رسانه فقط وقتی دانلود می‌شود که تنظیم منبع و دست‌کم یک مقصدِ آن اجازهٔ ارسال بدهند.
- وضعیت ارسال برای هر مقصد و هر بخش پیام ثبت می‌شود. اگر ارسال بخشی خطا بخورد، برنامه می‌تواند همان بخش را دوباره تلاش کند و بخش‌های موفق را در آن تلاش تکرار نمی‌کند.
- آخرین شناسهٔ پردازش‌شده در دیتابیس می‌ماند و در پنل قابل مشاهده است. رسانهٔ موقت پس از پردازش حذف می‌شود و پاک‌سازی دوره‌ای فایل‌های قدیمی جا‌مانده هم اجرا می‌شود.

## ۵. اتاق رمزنگاری‌شده و تأیید دستگاه

با توکن یک دستگاه اختصاصی Matrix و عضویت بات در اتاق، Collector می‌تواند متن و فایل را به‌صورت رمزنگاری سرتاسری بفرستد. اگر Element پیام را با هشدار دستگاه تأییدنشده نشان می‌دهد، در پنل کنار سرور Matrix روی **تأیید دستگاه** بزنید.

- **ایموجی** در نشست تأییدشدهٔ **همان حساب بات** در Element درخواست را قبول کنید، نشانه‌های دو طرف را مقایسه کنید و در هر دو طرف تأیید کنید.
- **Recovery Key** برای تأیید بدون نشست دوم، کلید بازیابی همان حساب را وارد کنید.
- **ساخت کلید** اگر حساب هنوز کلید بازیابی ندارد و امکان استفاده یا ایجاد هویت امضای حساب وجود دارد، کلید تازه بسازید، آن را در جای امن ذخیره کنید و سپس ثبت کنید.
- **بازنشانی در صورت گم شدن کلید** کلید جایگزین را آماده و ذخیره کنید، رمز حساب بات را بدهید و حذف بکاپ و کلیدهای قبلی را صریحاً تأیید کنید. هویت رمزنگاری و بکاپ قبلی Matrix جایگزین می‌شوند و پیام‌هایی که کلیدشان فقط در بکاپ قبلی بوده ممکن است دیگر خواندنی نباشند.

عملیات حساس در HTTPS، روی `localhost` یا از آدرس مستقیم IPv4 خصوصیِ سرور پس از تأیید کاربر پشتیبانی می‌شوند. با HTTP خصوصی، ارتباط مرورگر و پنل رمزنگاری نشده است. برای جزئیات هر روش و نحوهٔ تشخیص دستگاه از [راهنمای رمزنگاری و تأیید](docs/ENCRYPTION_SETUP.md) استفاده کنید.

## ۶. نگه‌داری داده و به‌روزرسانی

Compose این مسیرها را کنار فایل خودش می‌سازد.

| پوشه | محتوا |
| --- | --- |
| `mongo-data/` و `mongo-config/` | فایل‌ها و تنظیمات MongoDB |
| `matrix-crypto/` | کلیدها و وضعیت رمزنگاری دستگاه‌های Matrix |
| `storage/` | مسیر ذخیره‌سازی محلی |
| `temp/` | رسانه‌های موقت در حال پردازش |

داخل یک سرویس MongoDB، پنج دیتابیس جدا با پیشوند `telegram_collector_` برای `auth`، `telegram`، `matrix`، `settings` و `delivery` وجود دارند. این دیتابیس‌ها اطلاعات مدیر و نشست، حساب‌ها و کانال‌های تلگرام، سرورها و مقصدهای Matrix، تنظیمات و وضعیت ارسال را نگه می‌دارند. در اولین اجرا روی دیتابیس قدیمی، برنامه رکوردهای نسخهٔ تک‌دیتابیسی را به ساختار جدید کپی می‌کند.

برای ارتقا، از همان پوشهٔ Compose اجرا کنید.

```sh
docker compose pull backend
docker compose up -d --wait
```

داده‌ها با ری‌استارت و ساخت دوبارهٔ کانتینر حفظ می‌شوند، به شرطی که پوشه‌های متصل را نگه دارید. برای جابه‌جایی نصب، از دیتابیس و `matrix-crypto/` بکاپ بگیرید. اگر نصب قدیمی از volumeهای نام‌دار استفاده می‌کند، پیش از جابه‌جایی داده‌های MongoDB را در سرویس جدید بازیابی و کلیدهای Matrix را منتقل کنید. ایمیج عمومی دادهٔ حساب ندارد و فایل‌های داده و بکاپ در فهرست‌های نادیده‌گیری Git و Docker قرار دارند.

برای دیدن وضعیت و لاگ‌ها از این دستورها استفاده کنید. Compose برای هر سرویس از `json-file` با حداکثر سه فایل ۱۰ MB استفاده می‌کند.

```sh
docker compose ps
docker compose logs -f backend
```

## ساخت از سورس

از ریشهٔ سورس اجرا کنید. فقط در صورت اجرای ایمیج محلی، مقدار `COLLECTOR_TAG` را `local` بگذارید.

```sh
docker compose pull mongodb
docker build -t gigplus/telegram_collector:local .
COLLECTOR_TAG=local docker compose up -d --pull never --wait
```

در PowerShell، به‌جای تعیین متغیر در ابتدای دستور، ابتدا `$env:COLLECTOR_TAG = 'local'` را اجرا کنید. نسخهٔ Compose منتشرشده روی `latest` تنظیم است.
